## 三、错题分析

### 错题 1 · 第 1 题（0 / 5 分）

**题干**：下面是 ArkTS 中常量名、枚举值名推荐的代码是？

| 选项 | 内容 |
|---|---|
| A | 全小写，下划线分割 |
| B | 大驼峰 |
| C | 小驼峰 |
| D | 全大写，下划线分割 |

- **张三作答**：C
- **标准答案**：**D**
- **判定结论**：错误，得 0 分

**错误分析**
把「变量命名规范」错套用到了常量上。ArkTS 编程规范对四类标识符的命名要求是各自独立的，选项 A、B、C 分别对应其他类别的规范，属于典型的混淆项：

- 选项 A（全小写下划线）是**文件名、目录名**的常见写法，不是常量规范；
- 选项 B（大驼峰 UpperCamelCase）是**类名、枚举名、命名空间名**的规范；
- 选项 C（小驼峰 lowerCamelCase）是**变量名、方法名、参数名**的规范。

**知识点讲解（ArkTS 编程规范-命名）**

| 标识符类别 | 命名风格 | 示例 |
|---|---|---|
| 类名、枚举名、命名空间名 | 大驼峰 UpperCamelCase | `class User`、`enum UserType` |
| 变量名、方法名、参数名 | 小驼峰 lowerCamelCase | `let userName`、`sendMsg()` |
| **常量名、枚举值名** | **全大写 + 下划线** | `const MAX_USER_SIZE = 10000` |

记忆要点：**越「固定不变」的东西越用大写**——常量与枚举值在编译期就确定，因此用全大写加下划线。

### 错题 2 · 第 2 题（0 / 5 分）

**题干**：用哪一种装饰器修饰的组件可作为页面入口组件？

| 选项 | 内容 |
|---|---|
| A | @Entry |
| B | @Component |
| C | @Builder |
| D | @Preview |

- **张三作答**：B
- **标准答案**：**A**
- **判定结论**：错误，得 0 分

**错误分析**
混淆了「自定义组件」与「页面入口组件」两个概念。`@Component` 只是把结构体声明为一个**可复用的自定义组件**，它本身不承担页面入口职责；选项 C、D 则完全不属于组件声明类装饰器。

**知识点讲解（ArkUI 装饰器）**

| 装饰器 | 职责 | 关键约束 |
|---|---|---|
| **@Entry** | 标记**页面入口组件** | 一个页面**有且仅有一个** @Entry 组件 |
| @Component | 声明自定义组件 | 可复用，需与 @Entry 或 @Reusable 等配合 |
| @Builder | 定义轻量化 UI 构建函数 | 是函数不是组件，用于抽取重复 UI |
| @Preview | IDE 预览 | 仅用于 DevEco Studio 预览，不参与运行时 |

记忆要点：**入口只有一个，就是 @Entry**。实际工程中通常写成 `@Entry` + `@Component` 叠加修饰同一个 struct，这可能是误选 B 的原因——但问的是「哪一个装饰器使组件成为页面入口」，答案只能是 @Entry。

### 错题 3 · 第 10 题（0 / 5 分）

**题干**：「一次开发，多端部署」指的是一个工程，一次开发上架，多端按需部署。为了实现这一目的，HarmonyOS 提供了几个核心能力，如下哪个**不是**一多开发的核心能力？

| 选项 | 内容 |
|---|---|
| A | 多端分发机制 |
| B | 多端开发环境 |
| C | 多端协同能力 |
| D | 多端开发能力 |

- **张三作答**：D
- **标准答案**：**C**
- **判定结论**：错误，得 0 分

**错误分析**
把「全场景协同」的能力误并入「一多」的能力集合。一多的三大核心能力恰好是 A、B、D 三项，而 **C「多端协同能力」属于全场景协同（自由流转）范畴**，是与一多并列的技术理念，不属于一多的组成能力。

**知识点讲解（一次开发多端部署）**

一多的三大核心能力：

| 核心能力 | 作用 |
|---|---|
| 多端开发环境 | 提供多设备双向预览、分布式调试、超级终端模拟等开发支撑 |
| 多端开发能力 | 一套代码通过自适应/响应式布局与 SysCap 能力集适配多端 |
| 多端分发机制 | 应用包按设备能力集按需分发、安装与运行 |

与之并列、但**不属于一多**的能力块：**全场景协同**（多端协同、跨端迁移、跨端分享等自由流转能力）。

记忆要点：一多解决的是「**一套代码怎么跑到多种设备上**」；全场景协同解决的是「**任务怎么在不同设备之间流转**」。两者的目标不同，不要混为一谈。

3. **区分两个能力块**：用一句话概括一多（一套代码跑多端）与全场景协同（任务跨端流转），并各自默写出组成能力，避免再次互相串门。
4. **保持优势项**：`preferences`、`http` 权限、`Resource`、折叠屏体验设计、`Flex` 布局、组件分类与各类组件特性共 14 个知识点全部满分，说明组件层与布局层的实操知识扎实，只需补齐语言规范与体系结构两块短板。
